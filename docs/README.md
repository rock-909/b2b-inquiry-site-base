# B2B Inquiry Site Base Docs

docs/ 只保留当前项目真相、维护操作、正式上线标准、仍有效的技术问题与决策。过程材料、审查证据和可由 Git 恢复的历史计划不在这里长期保留。

## 核心入口

| 目标 | 入口 |
| --- | --- |
| 了解项目 | `项目.md` -> `技术栈.md` |
| 理解链路 | `架构与行为.md` |
| 修改业务身份或内容 | `项目.md` |
| 整体换品牌视觉 | `design/设计真相.md` -> `src/app/theme.css` |
| 开发和 CI | `开发与维护.md` |
| 判断正式上线 | `正式上线标准.md` |
| 查技术问题、迁移或长期取舍 | `技术问题与决策.md` |
| 改组件或页面 UI | `design/设计真相.md` -> `design/组件治理.md` |

## 受控临时文档

| 文档 | 独立保留原因 | 退役条件 |
| --- | --- | --- |
| `OpenNext Draft适配器.md` | Cloudflare 基线依赖固定的 Cache Components 预览包和 Node proxy bundler 补丁 | 正式版本同时覆盖 Node proxy、Cache Components 和 instrumentation 修复 |
| `TypeScript 7双轨迁移.md` | TS7 CLI 与仍依赖旧 compiler API 的工具链并存，需要跟踪多个上游的支持窗口 | 项目完成单轨 TS7 迁移 |

## 规则

代码、配置和运行态优先于文档。文档不得维护固定版本表、提交快照、完成计数或历史材料索引。

只有当前配置依赖尚未稳定的外部上游、需要持续检查状态且必须保留明确回滚路径时，
才单独建立受控临时文档。这类文档可以记录已经验证的固定 commit、版本和带日期的
上游状态快照，但必须同时写明实时来源、重新检查触发条件、迁移步骤和回滚方法；部署
或升级前必须重新查询实时状态，不能把旧快照当成当前批准。

达到退役条件后，把仍然有效的稳定结论合并回 `技术栈.md` 或 `开发与维护.md`，临时
文档不继续留在 docs 目录。不要为普通依赖升级、单次故障或已完成计划新增独立文档。
