## F05 — Route test lane：五份 mock 注册壳

**位置**：`src/app/api/inquiry/__tests__/route-harness.ts` + 5 个 lane 文件（request-admission / rate-limiting / payload-validation / turnstile-gate / lead-delivery）

### 背景

第一轮整改（PR #31）把 39 个 route 测试拆成 5 个 lane，共享 `route-harness.ts`。harness 收口了 mock **函数**（`routeMocks` 里的 `vi.fn()`），但每个 lane 文件仍各自复制 6 条 `vi.mock(...)` 注册。

### 为什么它是债

1. **维护点 ×5**：新增 route boundary 或改 mock 的 module path 时，5 个文件需同步改，漏一个就是静默行为差异。
2. **一致性靠人工核对**：某个 lane 忘了补新 mock，该 lane 会悄悄用真模块，极难发现。
3. **重复样板**：文件变长、diff 噪音大，掩盖行为断言。

### 为什么留存（NO-GO 论证）

- `vi.mock()` 是 vitest 静态提升机制：必须在文件顶层声明、按文件作用域生效，不能安全移入普通 helper。
- 集中到全局 setup 会让 mock 全局生效、跨 lane 串扰 —— 破坏 lane 隔离（拆 lane 的核心价值）。
- 收益/风险不对称：删除静态注册样板需引入 hoisting 魔法或破坏隔离。`routeMocks` 已收口可变状态，重复的只是静态注册声明，行为正确性有测试保证。

### 触发重估条件

- 新增第 6 个 lane 时重新掂量
- vitest 大版本引入更干净的共享 mock 原语
- 有人改 mock path 时实际踩坑漏改

## F06 — 负向契约：保护"某东西不存在"

**位置**：`/security-policy.txt` 404 实现、已删除 blog 的断言、退休 surface 的 no-store 断言等

负向断言只在保护当前对外行为、安全边界或已证明的回归风险时保留，例如真实 HTTP 404。不能因为断言保护“某东西不存在”就一律保留；仅检查旧文件名、组件名或历史拆分形状的断言应删除，已有行为测试覆盖的重复断言也不再维护。

**触发移除条件**：对应 surface 真正重新上线时，删除保护并恢复正向契约。

## F04-impl — `sharedToolingRules` 共享语义的隐性成本

R2-F04 整改（PR #40）把 `config-and-dev-tools` 与 `scripts` 两个 block 的 22 条逐字相同规则抽为共享常量。代价：未来修改一条共享规则会**同时影响两个 scope**。这是共享语义的预期代价（常量上方注释已写明）。经 `eslint --print-config` 全 23 文件矩阵对账证明零行为变化。

**触发拆分条件**：两 scope 对某条共享规则的需求开始分叉（一个要 warn 一个要 off），此时把该规则从共享常量移回各自 block。
