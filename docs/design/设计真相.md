# 设计真相

## 当前方向

当前站采用克制、工程可信的 B2B 视觉方向：先让买家理解产品和规格，再用结构、线条和少量动效建立品牌识别。页面不能用装饰掩盖产品事实、性能限制或询盘入口。

方向 E 是负责人已裁决的当前视觉候选；该编号随[模板导入提交](https://github.com/rock-909/b2b-inquiry-site-base/commit/a60ed413a71db54f8378fcc5985ad196b7fcd223)进入仓库。当前受跟踪文件未提供可定位的 HTML 样稿入口，不能仅凭编号还原设计；HTML 样稿也不是运行真相。其未完成落地约束必须在实现前重新验证；与当前代码、UI 实现规则或无障碍行为冲突时，以运行行为和明确的新裁决为准。

## 硬边界

- 主内容和主要 claim 默认可见，不依赖 JavaScript reveal；
- 设计优先复用正式 UI 入口；
- 颜色、网格、页面模式和动效由本文负责，代码级组件边界由 [UI 实现规则](../../.claude/rules/ui.md) 负责；
- 不为了高级感增加长动画、客户端边界或新依赖；
- reduced-motion、键盘焦点、对比度和窄屏布局是基本要求。

## 已确认的共同原则

| 原则 | 当前要求 |
| --- | --- |
| 内容先于装饰 | 首屏先回答“这是什么、适合谁、下一步是什么”；标题和核心结论先于图片、渐变和动效。装饰不能替代产品事实、规格、证据或交付边界；删除装饰后信息仍成立时，优先删除装饰。先让采购人员完成判断，再用线条、图片和微动效建立识别度。 |
| 一个区块回答一个主要问题 | 区块应回答产品身份、适用场景、规格匹配、配置、交付、可信证据或询盘动作；没有明确问题时，不因为“页面看起来完整”而保留。 |
| 层级与行动 | 用字号、字重、间距、位置和对比度建立层级；一个页面只保留一个主要行动，次要动作降低视觉权重但保持可发现性。不同时堆叠过大的字号、粗阴影、强渐变、厚边框和多种卡片。 |
| 留白与窄屏 | 区块间距表达内容关系，相关内容靠近，不相关内容拉开。留白不能使首屏缺少产品事实或 CTA；窄屏保留阅读顺序和触控空间，不机械缩小桌面。 |
| 颜色语义 | 浅色或中性背景；蓝色用于主要行动、技术可信和信息强调，不平均铺满页面；绿色/黄色/红色分别表达成功、警告、错误等状态，状态不能只依赖颜色。派生站默认继承，颜色变化必须有业务、可访问性或状态需要，不为制造差异换肤。 |
| 行为先于表面 | 按语义结构 → 默认行为 → 键盘与焦点 → 响应式边界 → 状态反馈 → 视觉 Token → 动效实现。外部组件正式使用前，必须统一项目 Token、内容结构、状态、响应式和无障碍行为。 |

## 设计系统

`src/app/theme.css` 是网站整体视觉主题的运行真相，也是 Agent 接到“换品牌风格”任务时的第一入口。它包含少量视觉原料、组件实际使用的语义角色，以及圆角、控件高度、阴影和动效等少量全局质感参数。`src/app/globals.css` 只负责把这些值接入 Tailwind，并维护全局 focus、reduced-motion、动画和基础样式。

Token 是方便修改的入口，不是限制层：整体换肤先改 `theme.css`；组件结构或 variant 改 `src/components/ui/*`；页面需要特殊设计时直接改页面或领域组件。组件默认使用背景、正文、弱文本、边框、品牌强调、状态和反差文字等语义角色，不直接引用底层视觉原料，也不在页面复制颜色、圆角、阴影或近似 token。

网格只用于建立内容节奏和装饰锚点，不得遮挡正文、焦点环或主要 CTA。设计系统变化至少检查桌面/移动布局、主题对比度、键盘焦点和首屏内容可见性。

## 页面模式

页面按标题和核心 claim -> 产品或证据 -> 规格/解释 -> CTA 或询盘入口组织。产品页先说明产品身份和适用场景，再呈现规格、图示、下载和询盘入口；示意图不能冒充工程证据。

CTA 要说明下一步动作。表单只保留必要字段，错误就地、可读、可恢复。窄屏优先保证正文、规格、键盘顺序和触控目标，布局不能依赖 hover，主要入口不能被动效或 sticky 装饰遮挡。

产品详情默认保留七类采购信息：产品事实、应用场景、规格、材料、配置方式、交付边界和可验证证据。[产品配置](../../src/config/offerings.ts) 是这些内容的唯一入口；示例文字只说明派生项目应该填写什么，不代表真实产品参数。只有业务本身确实不适用时，才调整区块，而不是为了让派生站看起来不同而删减。

## 动效

动效只能解释状态、层级或导航路径。优先 CSS、现有 state 属性和浏览器能力，不为“高级感”增加页面级 reveal、长 duration、新 motion 依赖或整页 Client Component。

静态营销内容保持服务端渲染，首屏 claim 默认可见，动效失败时内容仍完整可读。必须尊重 prefers-reduced-motion，避免破坏键盘焦点、读屏顺序、布局稳定性和 LCP；动效变更至少检查无 JS、reduced-motion、窄屏、键盘和真实浏览器行为。

## 方案与审查

### 模块与输入

AI 和外部模块只提供原料，不能凭空决定页面结构或品牌风格。按买家任务 → 模块类型 → 比较 2～3 个参考 → 提取行为和结构 → 接入现有 Token 与组件 → 组合页面 → 系统一致性和质量审查推进。

- 适合模块组装：产品卡片、规格表、参数对照、应用场景、材料说明、配置选项、证据列表、询盘表单、筛选控件、状态反馈、主题切换、展开/收起、下载反馈和错误提示。
- 不适合直接拼装：首页 Hero、品牌核心叙事、产品定位、应用说明、交付边界、认证与证据表达、询盘字段和地区内容。它们必须来自业务事实、买家任务和证据，不能从组件市场推导。
- 给 Agent 的输入至少包括：页面任务和买家、具体 UI 问题、当前设计内核、可参考模块、必须继承的 Token/组件/行为、不能复制的品牌外观，以及无障碍、响应式、性能和 no-JS 条件。
- 先比较参考并说明取舍，再实现；不要直接复制完整页面、完整组件库或未经筛选的代码。

### 视觉候选与 AI/Figma

生成多个候选时，至少在内容密度、网格结构、图片角色、证据表达、排版比例、视觉节奏中的两个维度形成明确差异，不能只换颜色、渐变或字体。先淘汰最接近默认模板的方案，再按买家任务、产品事实和当前设计内核选择；禁止项不能代替设计取舍。

是否启用 Stitch/Figma 按[派生站工作流](../派生站工作流.md#stitchfigma)决定。AI 视觉生成只能在页面内容包和低保真结构批准后使用；启用后，将设计规范、Token、组件边界和禁止项作为约束，生成 2～3 个候选，转入 Figma 比较和调整，再回到仓库实现，最后做浏览器、无障碍和性能验收。

AI 视觉生成适合比较首屏比例、图文关系、规格/证据/CTA 构图、页面密度、留白和品牌氛围；不能替代业务事实、SEO、买家任务、页面内容包、表单、键盘、状态、响应式和无 JavaScript 行为、生产组件、内容源、测试和部署契约。AI 生成图用于探索，Figma 用于协作确认，生产代码与真实浏览器行为才是最终实现。生成结果不得直接覆盖仓库，也不能凭视觉稿跳过低保真结构或运行时验证。

### 双通道设计审查

设计结果不得只由生成它的同一个 Agent 自评。两个审查通道互不影响：

| 通道 | 检查内容 |
| --- | --- |
| 品味审查 | 层级、节奏、克制、模板感和买家理解成本 |
| 确定性审查 | 事实、对比度、键盘、状态、窄屏、no-JS、性能和浏览器行为 |

主 Agent 综合两路结果，分别记录“必须修复”“可以接受”“不属于当前范围”。确定性检查通过不代表视觉方案有品味，品味认可也不代表运行行为成立。

## 设计审查速查表

- [ ] 首屏说清产品、买家和下一步；每个区块回答一个买家问题，规格、交付边界和证据没有被装饰掩盖；主要 CTA 只有一个且动作明确。
- [ ] 用户知道哪些元素可操作，操作后有反馈；错误可理解、可修复；默认、Focus、Loading、Error、Empty 等适用状态齐备，关闭动画仍能完成任务。
- [ ] 颜色、字体、间距、圆角、边框和阴影来自同一系统；相同语义的组件行为一致，蓝色只强调必要内容，留白表达分组，不制造空洞。
- [ ] 未新增无必要依赖、客户端边界或动画；320px/375px、键盘、200% 缩放和 reduced-motion 均成立。
- [ ] 无 JavaScript 时正文和询盘入口可用，参考细节不损害性能。模块组合若像来自不同网站，退回筛选或统一 Token，不继续叠加装饰。

## 读取顺序

设计调整先读本文和[主题入口](../../src/app/theme.css)；涉及代码边界时再读[UI 实现规则](../../.claude/rules/ui.md)。需要比较外部案例时，按任务查阅[设计参考](设计参考.md)；派生研究与内容批准顺序见[派生站工作流](../派生站工作流.md)。历史视觉翻译、样稿和被否方向不作为当前规则。
