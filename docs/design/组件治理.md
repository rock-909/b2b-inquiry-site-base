# 组件治理

## 正式入口

正式 UI 入口是 src/components/ui/* 和现有领域组件。新页面先复用已有组件，再证明为什么需要新变体。不要在页面文件里复制按钮、字段、卡片或状态样式。设计和页面规则见 `设计真相.md`。

## 组件边界

每个组件只承担清晰的视觉或交互责任。Server Component 默认优先；只有真实浏览器状态、输入或交互需要时才使用 Client Component。组件 API 要保持可组合、可访问和可测试。

## Storybook 与验证

Storybook 只覆盖需要独立展示和交互验证的组件，不维护一份与代码重复的全量清单。组件变更运行相关单测、组件治理检查和必要的浏览器验证。

## 文案和状态

用户可见文案走 messages key。错误、加载、禁用、焦点和 reduced-motion 状态必须有明确表现。不要用空壳组件、隐藏副本或仅供测试的 wrapper 冒充正式入口。
