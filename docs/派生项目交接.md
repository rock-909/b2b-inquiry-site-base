# 派生项目交接

这是从本模板复制、fork 或继续演化站点时的交接清单。它负责“派生后要替换和重新证明什么”；`docs/正式上线标准.md` 仍是能否对外宣称上线的唯一判决正本。

## 派生边界

- 会跟随：Git 中已跟踪的代码、测试、docs、`AGENTS.md` / `CLAUDE.md`、`.claude/rules/**` 和 `.claude/skills/**`。
- 不会跟随：`.env*` 中的真实密钥、Airtable / Resend / Turnstile / Cloudflare 账号资源、DNS、GitHub ruleset 和 branch protection。
- 模板的 CI 或 `release:verify` 通过，不等于派生站已配置 provider、已部署或已正式上线。
- 派生站创建后，本文档的复选状态必须从未完成开始，不继承另一个站点的上线证据。

## 第一轮必须替换

- 仓库与所有权：新 remote、默认分支、workflow 权限、Cloudflare 项目和负责人。
- 业务真相：`src/config/single-site*.ts`、`src/config/public-trust.ts`、`src/config/offerings.ts`、`src/content/pages/**`、`messages/**` 和真实 offering 页面。
- 品牌与法务：域名、联系方式、logo / favicon / OG 资产、主题 token、Privacy、Terms 和对外声明。
- 部署与询盘：按 `.env.example` 重新配置 Turnstile、rate limit、Airtable、Resend 和 Cloudflare Secrets，不复制真实凭据。
- 文档与 AI 入口：更新 `README.md`、`docs/项目.md`、`docs/架构与行为.md`、`docs/技术栈.md`、`docs/开发与维护.md`、本文档、`AGENTS.md` 中的项目事实和项目内 skills 的路径/链路。

`docs/OpenNext Draft适配器.md` 和 `docs/TypeScript 7双轨迁移.md` 只在派生项目仍使用相同 pin、补丁或双轨方案时保留；退役条件成立后按各文档说明收口。

## 规则和 skills 跟随

- 保留安全、询盘、无障碍、Cloudflare/OpenNext 和上线证明边界，不因换品牌删除。
- `.claude/rules/*.md` 的 `paths:` 必须与派生项目的实际目录一致；路径或运行链改变时同步修改。
- `repo-health-audit` 的 `site-audit-profile.md` 必须改成派生站的 offering、询盘和发布真实链路。
- `intent-review` 和 `react-doctor` 只保留当前项目真实存在的命令、文件和门禁；不保留旧模板路径或已退役 workflow。
- 派生工作使用 `.claude/skills/derive-site/SKILL.md` 作为薄入口；本文档是清单正本，skill 不再复制一份。

## Owner 与上线清单

- [ ] 决定 Airtable 使用低频人工复核，还是为“邮件失败但 Airtable 成功”的记录配置自动提醒。
- [ ] 配置真实 Airtable base、table 和 PAT。
- [ ] 配置真实 Resend API key、发件域名和 owner 收件邮箱。
- [ ] 真实部署后运行 Airtable canary，并核对 API 响应与 Airtable 记录使用同一 `referenceId`。
- [ ] 单独确认 Resend provider 状态和 owner 收件箱实际收件。
- [ ] 人工确认正式域名、DNS、TLS 和 Cloudflare custom domain。
- [ ] Owner 确认联系信息、法务文本、品牌内容和最终上线。
- [ ] 按实际协作需要配置 main branch protection；未配置时只能记录“未强制”，不能把 CI 存在写成外部门禁已生效。

前七项是正式上线的业务/平台证据；第八项是仓库治理，在协作模式需要时启用。

## 交付时只记录这些

- 派生源 SHA 和派生项目 HEAD。
- 已替换的业务、文档、rules 和 skills 入口。
- 已运行的本地、CI、部署和 provider 证明。
- 仍缺失的真实账号、凭据、域名或 Owner 决策。
