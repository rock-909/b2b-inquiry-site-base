# 正式上线标准

这是公开上线的唯一判决正本。任何一层通过都不能自动替代下一层。

## 1. 本地工程证明

至少按改动范围运行 type-check、lint、相关 Vitest、内容检查、必要 Playwright，以及普通和 Cloudflare 构建。构建必须串行，验证必须针对当前 SHA。

## 2. PR CI 与合并门禁

PR CI 证明声明的检查在 GitHub runner 上执行且通过。还要确认 required status checks、branch protection 和失败传播；看不到外部设置时只能写“检查存在，外部强制力未证实”。

## 3. Release proof

pnpm release:verify 证明当前 checkout 满足 release manifest 的技术序列，包括内容、类型、测试、构建、Cloudflare 生成物、静态资源 header 和 Wrangler dry-run（若凭据可用）。

release proof 不是 public launch proof。固定 SHA、测试总数、warning 数量和一次绿灯不能成为永久标准。

## 4. 部署验证

在真实部署地址运行 deployed smoke，确认公开页面、路由、静态资源、PDF noindex、表单表面和错误路径。预览地址不能冒充正式生产地址。

workflow_dispatch 的 preview 分支只做“传入外部 URL 能否打开”的 surface smoke；它不构建、不部署，也不证明该 URL 对应当前 SHA 或当前构建产物。

## 5. 真实业务验证

使用真实生产配置和真实部署地址做 Airtable write canary，确认 Turnstile 后的表单提交能写入 Airtable。它不证明 Resend 送达或 owner 收件；这两项必须由对应系统记录和 owner inbox 回执单独确认。

## 正式通过条件

以下全部满足才可称为正式上线：

- 本地工程证明通过；
- PR required checks 通过且外部强制力已确认；
- Cloudflare 构建和部署证明通过；
- 真实生产地址 smoke 通过；
- Airtable write canary 通过；
- Resend 状态和 owner inbox receipt 已单独确认；
- owner 确认业务、法务和联系信息。

缺少任何一层，只能报告“部分证明”或“未证实”，不能报告“已正式上线”。
