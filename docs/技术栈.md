# 技术栈

本文档解释当前采用的技术及职责；精确版本以 package.json、lockfile、Next 配置和部署配置为准。

## 运行与构建

- Next.js：页面、路由、metadata 和服务端渲染；
- React：组件和交互；
- TypeScript：类型边界；
- pnpm：依赖和脚本入口；
- OpenNext + Cloudflare Workers：生产构建和运行；
- Wrangler：Cloudflare dry-run、部署和平台语义验证。

pnpm build 与 pnpm website:build:cf 写入同一个 .next，不能并行运行。Playwright webServer 也可能重建 .next；Lighthouse 使用独立的 .next-lighthouse。

当前 TypeScript 统一使用 6.0.2：项目类型检查、Next.js JavaScript compiler API、
ESLint 及其他工具共享同一个 CLI 与 compiler API 基线。版本策略是“最新稳定兼容版本”，
不是把所有包机械升级到最大版本。

升级时优先使用正式 stable；与 Next.js、TypeScript compiler API、ESLint parser、
OpenNext/Cloudflare 强耦合的工具使用 latest compatible stable。canary、beta、rc 和
experimental 默认不进入主线。每次升级都要用真实 peer range、干净安装、type-check、
lint、test、Next build、OpenNext build 和必要的 runtime proof 证明组合兼容；不能用
override、force 或关闭门禁制造绿灯。具体版本以 `package.json`、lockfile 和当前验证结果为准。

Cloudflare 基线使用精确固定的 OpenNext 正式 stable、R2 incremental cache，以及
正式版本内置的 Node `src/proxy.ts` bundler。Cache Components 和 Partial
Prefetching 在 OpenNext 正式支持并完成独立 runtime proof 前保持关闭。

## 内容与国际化

- src/content/pages/{locale}/*.ts：各语言页面正文和页面级 SEO 输入，直接进入 Next/OpenNext 模块图；
- `messages/base/{locale}/messages.json`：UI 文案；
- src/config/pages.config.ts：静态页面注册；
- locale 配置、messages 和静态页面模块必须一起维护；
- 当前示例公开 English + Spanish：英语使用无前缀路径，西班牙语使用 `/es/`；新增语言必须同步 locale 配置、消息包、页面内容、offering 文案、metadata、sitemap 和测试。

## UI 与主题

- Base UI：负责 Dialog、Popover、Select、Combobox 等复杂交互 primitive；
- `src/components/ui/*`：项目正式 UI 入口，业务代码不直接依赖 Base UI；
- 原生 HTML：普通按钮、输入框和 textarea 等浏览器已有可靠语义的控件；
- Tailwind CSS + `src/app/theme.css`：页面样式和网站整体换肤。

精确 Base UI 版本以 `package.json` 和 lockfile 为准，不在本文维护版本号。

## 询盘与安全

询盘链路由统一表单、服务端验证、Turnstile、下游 provider 和 owner receipt 组成。Resend 是 owner 日常处理询盘的主通道，Airtable 是结构化备份；两者使用同一引用号并行交付，Airtable 不再记录邮件成功与否。任一渠道成功即接受，两者都失败才让买家重试。

敏感配置来自环境变量和平台 secrets，不写入文档或测试 fixture。

## 测试和质量

- Vitest：单元、集成和架构行为；
- Playwright：浏览器和部署 smoke；
- ESLint、type-check、content/i18n checks：提交和 CI 基础门禁；
- architecture/dependency/Cloudflare checks：保护结构、生成物和平台语义。

质量门禁的五层定义、触发位置和证明边界统一见 `质量门禁.md`，本文不重复维护完整矩阵。

本地 Git hook、CI 和 release lane 的具体职责见 `质量门禁.md`。首次在某个 worktree
使用时运行 `pnpm hooks:install`；hook 解析不依赖其他 worktree 的绝对路径。
