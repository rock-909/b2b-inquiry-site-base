# 技术栈

本文解释技术职责、升级原则和平台取舍。精确版本与运行配置以文末的[版本真相](#版本真相)入口为准；仍存在的依赖告警见[技术债](技术债.md#开发依赖审计)。

## 运行与构建

- Next.js：页面、路由、metadata 和服务端渲染；
- React：组件和交互；
- TypeScript：类型边界；
- pnpm：依赖和脚本入口；
- OpenNext + Cloudflare Workers：生产构建和运行；
- Wrangler：Cloudflare dry-run、部署和平台语义验证。

pnpm build 与 pnpm website:build:cf 写入同一个 .next，不能并行运行。Playwright webServer 也可能重建 .next；Lighthouse 使用独立的 .next-lighthouse。

## 升级原则

项目类型检查、Next.js JavaScript compiler API、
ESLint 及其他工具共享安装的 TypeScript 基线。版本策略是“最新稳定兼容版本”，
不是把所有包机械升级到最大版本。

升级时优先使用正式 stable；与 Next.js、TypeScript compiler API、ESLint parser、
OpenNext/Cloudflare 强耦合的工具使用 latest compatible stable。canary、beta、rc 和
experimental 默认不进入主线。每次升级都要用真实 peer range、干净安装、type-check、
lint、test、Next build、OpenNext build 和必要的 runtime proof 证明组合兼容；不能用
override、force 或关闭门禁制造绿灯。具体版本以 `package.json`、lockfile 和当前验证结果为准。

### 发布冷却期

依赖解析使用 pnpm 默认发布冷却期（`minimumReleaseAge` 默认 1440 分钟；`pnpm-workspace.yaml`
不显式设置，保持默认的非 strict 行为），不全局关闭。Next.js 正式版本族（`next`、`@next/*`、
`eslint-config-next`）在 `minimumReleaseAgeExclude` 中按包名整体豁免，使 `latest` 能在发布当天解析；
该豁免不区分 stable 与 prerelease，canary、rc、beta 仍不得进入主线，由评审把关。其余依赖保持冷却：
范围与 dist-tag 只解析已满 24 小时的版本；精确钉版若尚未满期，pnpm 会自动在
`minimumReleaseAgeExclude` 追加版本条目，评审时应确认并写明原因，或在满期后移除。
`--frozen-lockfile` 安装不会重新筛查已锁定版本。

### 已有例外

允许的例外都是已知且有原因的，新增前同样要写明原因：

- `peerDependencyRules.allowedVersions` 只放行 `eslint-plugin-import`、`eslint-plugin-react`、
  `eslint-plugin-jsx-a11y`，因为它们的最新版仍只声明 eslint <=9；上游声明 eslint 10 后删除对应条目；
- wrangler 依赖的 miniflare `-alpha` / `-beta` 是 Cloudflare 自己的发布线，不是我们单独选择的 prerelease；
- `experimental.turbopackRustReactCompiler` 是已在主线启用的 experimental 例外，
  不代表其他 experimental 可以进入主线；
- `experimental.agentFeedback: true` 与 `experimental.agentUpgrade: 'security'` 是 owner 决定启用的
  Next.js agent 工具例外：前者让 `next dev` 在 `AGENTS.md` 中维护 Next 托管的 agent-feedback 块，
  后者只在已安装版本命中已发布安全公告时提醒 agent 升级。两者仅限这两项，Next 托管的 `AGENTS.md`
  内容随 `next dev` 变化时一并提交，不手写其他内容。

## Cloudflare 基线与能力取舍

Cloudflare 基线使用精确固定的 OpenNext 正式 stable、只读 Static Assets incremental cache（不绑定 R2），以及
OpenNext 内置的 Node `src/proxy.ts` bundler。该 bundler 在上游构建日志和文档中标注为
experimental、不受 OpenNext 维护者保证，因此每次升级 OpenNext 都需要 preview Worker proof。
Cache Components 和 Partial Prefetching 在出现明确需求、OpenNext 正式支持并完成独立 runtime proof 前保持关闭。

### Cloudflare 能力评估（2026-10-17）

本次决定保持现状，只记录依据和重新评估条件，不修改代码或运行配置。
评估时页面内容来自仓库，更新通过重新构建和部署完成；没有内容后台、定时刷新或按标签失效的使用方。
当时的产品文字示例已随轻量底座改造移除，当前不含默认产品目录；Logo 尚未启用真实图片。当时的 R2 缓存和 Node 代理适配已有本地 Worker 验证记录；R2 缓存已在 2026-10-19 换成 Static Assets 只读缓存（见下表）。

| 项目 | 当前决定及依据 | 重新评估的触发条件 |
| --- | --- | --- |
| Cloudflare 兼容日期 | 使用 `2026-10-06`（兼容标志不变），仅在 wrangler 不低于 4.149 时使用，旧 wrangler 下该日期会使 preview 无法启动；OpenNext 构建会对早于 180 天的日期告警。兼容日期选择运行行为，不代表引擎和安全修复停在该日期。 | 稳定适配器提高最低日期要求；已复现问题对应某项兼容行为修复；新增功能需要更晚日期。满足条件后单独验证日期变化，不混入缓存或图片改造。 |
| Node 代理适配 | 保留 `src/proxy.ts` 和正式版 OpenNext 内置 bundler。语言路由、重写和缺失页面处理有真实使用方；适配器仍标注实验性质。 | 升级涉及代理打包或运行行为；出现可复现的代理兼容缺陷；稳定上游修复命中该缺陷。继续使用已有 Worker 验证，不为消除警告回退旧入口、强改 Edge 或维护私有适配补丁。 |
| 增量缓存（Static Assets 只读） | 使用 OpenNext 的 Static Assets 只读缓存，`wrangler.jsonc` 不再绑定 R2。2026-10-19 在 preview Worker 上测得，每个 HTML 文档、304 复访和 RSC 预取都读 R2，比未走缓存的响应慢约 220-300 ms；站点不使用运行时重新验证，内容更新靠重新构建和部署，R2 的运行时写入没有使用方。`opennextjs-cloudflare deploy` 和 `preview` 会自动把预渲染缓存复制进静态资源；直接用 `wrangler deploy` 时须先运行 `opennextjs-cloudflare populateCache`，日志应出现 “Successfully populated static assets cache”。 | 派生站需要运行时重新验证：海量程序化页面、秒级新鲜度或用户生成内容。届时改回 R2 incremental cache，给 preview 和 production 各绑定独立的 `NEXT_INC_CACHE_R2_BUCKET` 并填充，同时更新配置门禁。 |
| 区域缓存 | 不适用：只读 Static Assets 缓存之上没有远端缓存读取可省，保持关闭。 | 改回 R2 后测量显示其读取是页面延迟或成本的主要来源，且请求有可复用内容；试验能证明收益，并验证内容新鲜度和失效行为。 |
| ISR、标签缓存和重新验证队列 | 不新增队列、D1、Durable Objects 或标签缓存；仓库内容更新不需要运行时重新验证。 | 接入 CMS 等内容源，要求不重新部署即可更新；或明确需要按时间、路径、标签刷新。按实际刷新方式选择必要组件，不整套接入。 |
| Cache Components、Partial Prefetching | 继续关闭。当前没有已测得的动态页面或导航问题要求迁移；Partial Prefetching 依赖 Cache Components。 | 动态内容复用或导航体验出现明确需求和测量依据，并确认正式版 OpenNext 支持相应能力。启用前验证路由缓存、语言隔离、预取行为及实际部署的 Worker。 |
| Cloudflare 图片优化 | 保持 Cloudflare 构建的 `unoptimized` 策略，不新增 Images 绑定或自定义 loader；当前缺少需要优化的真实产品图。 | 真实图片上线后，图片成为首屏或传输量的主要问题；或大量图片、多尺寸、频繁上传使静态处理难以维护。先检查尺寸、压缩、响应式图片和加载方式，再比较静态产物与图片服务的收益、费用和维护成本。 |

证据边界：`reports/lighthouse/` 中 2026-09-08 的三份首页报告均记录图片请求为 0，最大内容元素为文字标题；这是历史本地测量，不能代表当前线上性能。
2026-10-17 的只读评估没有重新构建、部署或发送真实询盘，也没有测得线上流量、R2 延迟或真实产品图片负载；R2 延迟由 2026-10-19 的 preview 测量补上。
配置和消费者变化后，以当前代码及测量结果为准。

未出现上述触发条件时，沿用本次结论，不因日期变旧、上游发布新功能或理论性能收益重复做整套评估。
常规依赖升级仍按前述原则执行，只核对受影响的能力；安全、数据完整性、询盘交付或发布真实性问题不受性能收益门槛限制。
触发后，记录实际问题和消费者，复用 [Cloudflare 规则](../.claude/rules/cloudflare.md) 的证明要求及 [质量门禁](质量门禁.md)，不新增重复脚本或门禁。
本地 Worker 和 dry-run 不替代已部署环境的证明，也不构成部署或真实询盘授权。

官方依据（2026-10-17 核对）：[兼容日期](https://developers.cloudflare.com/workers/configuration/compatibility-dates/)、[兼容行为变化](https://developers.cloudflare.com/workers/configuration/compatibility-flags/)、[OpenNext 缓存](https://opennext.js.org/cloudflare/caching)、[OpenNext 图片优化](https://opennext.js.org/cloudflare/howtos/image)。

## 内容与国际化

- `src/content/pages/{locale}/*.ts`：各语言页面正文和页面级 SEO 输入，直接进入 Next/OpenNext 模块图；
- `messages/base/{locale}/messages.json`：UI 文案；
- [静态页面配置](../src/config/pages.config.ts)：静态页面注册；
- locale 配置、messages 和静态页面模块必须一起维护；
- 当前示例公开 English + Spanish：英语使用无前缀路径，西班牙语使用 `/es/`；新增语言必须同步 locale 配置、消息包、页面内容、派生站实际新增的业务文案、metadata、sitemap 和测试。

## UI 与主题

- Base UI：负责 Dialog、Popover、Select、Combobox 等复杂交互 primitive；
- `src/components/ui/*`：项目正式 UI 入口，业务代码不直接依赖 Base UI；
- 原生 HTML：普通按钮、输入框和 textarea 等浏览器已有可靠语义的控件；
- Tailwind CSS + `src/app/theme.css`：页面样式和网站整体换肤。

精确 Base UI 版本以 `package.json` 和 lockfile 为准，不在本文维护版本号。
