# 技术问题与决策

这里只记录仍影响当前行为、上线判断或产品真实性，且目前不能直接修复的事项。

## 待确认问题

### PDF 内容真实性与源文件

现状：网页已经撤下无依据的 ASTM G154-2016 和 EN 13501 B1 说法，但 `product-catalog.pdf` 和 `spec-sheet-tb-td.pdf` 仍有旧说法；6 份公开 PDF 都没有可访问性标签，`spec-sheet-tb-bw.pdf` 可提取文本很少，仓库也没有可靠源文件。

影响：买家下载后仍可能看到与网页不同的产品事实，PDF 的搜索和辅助阅读体验也较弱。

当前处置：不直接修改难以复核的二进制文件。拿到设计源文件后统一重导出，并同时核对网页、PDF、可提取文本和可访问性标签。

重新评估条件：owner 提供可编辑源文件，或决定重新制作整套下载资料。

### 管坝 MOQ 待确认

现状：网页和 `spec-sheet-tb-td.pdf` 都写着 `MOQ from 10 metres`，但当前没有 owner 确认材料。

影响：数值可能一致但不一定真实，不能把“两个地方都这么写”当成事实证明。

当前处置：暂不猜测或单边修改。owner 给出真实 MOQ 后，网页和 PDF 同批更新。

重新评估条件：owner 确认当前数值，或提供新的销售口径。

### Airtable 超时后的晚到请求

现状：询盘链路给 Airtable 8 秒等待预算；超时只会停止当前请求继续等待，底层 SDK 的重试不一定被取消。

影响：系统可能先记录失败，稍后 Airtable 又落下一条记录；买家重试时可能形成重复线索。

当前处置：先保持现有简单链路，不增加取消和幂等框架。前端继续缩短等待时间不能解决底层晚到问题。

重新评估条件：运行中出现晚到或重复记录，再评估 AbortSignal，或稳定 submission ID 配合 provider 幂等。
