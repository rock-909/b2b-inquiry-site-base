# 质量门禁

本文记录当前仓库实际执行的本地、CI 和发布检查。配置文件和脚本是执行真相；本文用于解释触发时机、失败含义和证明边界。

## 触发矩阵

| 位置 | 触发方式 | 当前检查 | 失败后入口 | 证明边界 |
| --- | --- | --- | --- | --- |
| `pre-commit` | `git commit` 自动触发 | 暂存文件清单对应的 Prettier、JS/TS ESLint、涉及 i18n 时的翻译同步 | 按 hook 输出修复对应文件 | 检查工作区文件，不是部分暂存字节的独立证明，也不证明全仓或构建 |
| `commit-msg` | `git commit` 自动触发 | commitlint | 修改提交信息 | 只证明提交信息格式 |
| `pre-push` | `git push` 自动触发 | 禁止直接推送 `origin/main` | 修复失败命令；feature branch 经 CI 合并 | 本地快速失败，不替代远端 CI |
| `pnpm website:check` | 开发者手动运行 | TypeScript、ESLint、Prettier、Vitest、Next build | 运行失败子命令 | 本地全仓工程检查，不含 OpenNext 和真实 Worker runtime |
| PR CI | PR 指向 `main` 或 `pr/**` 自动触发 | L1/L2 静态与架构、L3 Vitest/Playwright、Semgrep、L4 Next/OpenNext 构建和 artifact 合同 | 打开失败 job，运行同名本地命令 | GitHub runner 上的强制合并门禁；PR 同样执行无发布凭据的 Wrangler preview dry-run |
| `main` CI | push 到 `main` 自动触发 | 同 PR CI（含 Wrangler preview dry-run） | 打开失败 job；必要时本地运行 `release:verify` | exact `main` SHA 的构建证明，不等于部署成功 |
| `workflow_dispatch` CI | 手动触发 | 同 `main` CI | 同上 | 按需重跑指定提交的构建证明 |
| `pnpm release:verify` | 本地手动；production 部署 workflow 自动调用 | 配置、类型、lint、format、Vitest、Chromium、Next/OpenNext build、artifact、headers、Wrangler dry-run | 修复首个失败步骤后从头重跑 | release lane 证明；不部署，也不证明真实 provider 或正式域名 |
| Cloudflare 部署 workflow | 手动选择 preview/production | preview 外部 URL smoke；production main 完整 ref、同 SHA 的最新 main push CI、严格配置、Worker secret 名称检查、production release verify、部署及部署后 smoke | 按 workflow 失败步骤处理 | 只证明本次 workflow 的部署和 smoke 范围 |
| weekly browser matrix | 每周及手动 | 全浏览器矩阵、零重试 | 根据 Playwright artifact 修复 | 暴露低频浏览器失败，不是每个 PR 的重复 gate |
| weekly dependency audit | 每周及手动 | production 依赖 audit，失败时创建 issue | 升级或评估受影响依赖 | 依赖漏洞信号，不证明应用不可利用性 |

普通 feature branch 的单独 push 不触发 `ci.yml`；创建指向受支持目标分支的 PR 后才进入 PR CI。

## 五层证明

| 层级 | 自动入口 | 主要对象 |
| --- | --- | --- |
| L1 Static | pre-commit、CI quality、release verify | TypeScript、ESLint、Prettier |
| L2 Architecture | CI quality、Semgrep、Cloudflare config checks | import、配置、安全和平台静态合同 |
| L3 Behavioral | Vitest、Playwright、weekly browser matrix | 单元、集成和浏览器行为 |
| L4 Build | Next build、OpenNext build、artifact/client-boundary checks | 构建产物、预渲染、包体和平台配置 |
| L5 Runtime | local/deployed smoke、production workflow、provider canary | Worker HTTP、已部署表面和明确执行的外部写入 |

- ESLint 的 warning 在 `--max-warnings 0` 下同样阻断，不能把“降为 warn”理解成非阻断。
- client-boundary 产物报告只观测带表单标记的单个 chunk 大小，不设固定字节阻断，不是整个表单的总下载量；跨 chunk 的禁用依赖由 dependency-cruiser 源码可达性测试补充。静态图只解析可确定的 import，不证明任意运行时拼接路径。
- [Cloudflare 当前限制](https://developers.cloudflare.com/workers/platform/limits/#worker-size)（2026-09-08 核对）是 Free/Paid 均 64 MiB 未压缩 Worker bundle，以 Wrangler `Total Upload` 为观测口径；旧 3000 KiB gzip 自定义门禁已移除，gzip 不再决定发布检查成败。dry-run 保留，但不替代平台上传校验。

## Next.js 官方实践适配

| 实践 | 判断 | 当前做法 |
| --- | --- | --- |
| TypeScript、ESLint、Prettier、tests、build | `ADOPT` | 本地综合检查和 CI 均覆盖 |
| staged file 格式和 lint | `ADAPT` | 使用 Lefthook check-only，不自动改写未暂存内容，不新增 `lint-staged` |
| 专用静态/架构规则 | `ADAPT` | 只保留本项目有真实 failure mode 的 dependency-cruiser、Semgrep 和 architecture tests |
| monorepo Turbo、Jest、Rspack、Rust/SWC fixture | `NOT_APPLICABLE` | 本项目没有消费者，不引入 |
| canary-only Cache Components / Partial Prefetching gate | `DEFER` | 等 OpenNext stable 兼容后独立验证 |

## 重复检查的处理

同一命令在本地和 CI 重跑属于不同环境的执行重复：本地用于尽早失败，CI 用干净 runner 提供权威证明。不要为了消除命令重复而删除关键 proof。

也不要把所有检查塞进每一层：

- pre-commit 只处理暂存文件，不运行测试或构建；
- pre-push 只防误推 main；全量检查交给 PR CI，本地需要时手动运行 website:check 或 release:verify；
- CI 负责全仓、浏览器和 Cloudflare/OpenNext 构建；
- release verify 和部署 workflow 才处理发布前组合证明。

## 结构阈值复核

2026-08-28 使用 ESLint 对生产 JS/TS 实际测得：

| 规则 | 阈值 | 当前最大值 | 处理 |
| --- | ---: | ---: | --- |
| `complexity` | 15 | 14 | 保留，继续限制真实业务分支复杂度 |
| `max-depth` | 3 | 3 | 保留，第四层嵌套应先审查控制流 |
| `max-lines-per-function` | 120 | 120 | 保留，不因 JSX 行数机械拆分现有组件 |
| `max-params` | 3 | 3 | 保留，达到第四个参数时再判断是否有真实参数对象语义 |
| `max-nested-callbacks` | 2 | 2 | 保留，第三层回调需要明确可读性理由 |
| `max-lines` | 500 | 310 | 保留为宽松文件上限，不把文件长度当成拆分命令 |
| `max-statements` | 20 | 20 | 保留，达到上限的函数仍有单一可解释职责 |

多个最大值贴近阈值，但当前没有误报、豁免或只为过 lint 而拆分的证据。因此本轮不改规则、不重构生产代码；以后只有出现可复现误报或真实可读性问题时再调整。

## 本轮需求收缩

- 导航反馈使用 Next Link 原生 pending 状态，不模拟百分比或维护全站 click/popstate 计时器。
- 普通公开资料不要求必须被源码直接引用；发布者仍须确认公开许可及内容，不应发布秘密或个人资料。
- Lighthouse 使用中位数聚合，报告保留在本地 `reports/lighthouse`，不默认上传到公开临时存储；既有性能阈值未放宽。
- 2026-09-08 已启用 main 保护：必须 PR、CI 汇总成功且分支保持最新，管理员受约束，禁止强推/删除；因此移除 pre-push 的全量测试与构建。

## 证明边界

- React Doctor 对 `legal-page.ts` 的两处 `filter().map()` 保留单文件规则例外：输入是已解析的静态内容块，过滤保留 TypeScript 的 heading 类型收窄；这不是重复 Markdown 解析，没有已测得的性能问题，不为合并遍历改写业务代码。
- React Doctor 0.9.13 在工作树存在尚未暂存的删除时可能读取已不存在的 Git 跟踪文件，返回成功但报告 `complete: false`。本轮通过独立临时 Git 索引复核完整报告，未修改用户暂存区；新 react:doctor 入口会校验报告完整性，任何不完整、无法解析或非零问题结果均失败；仍有未暂存删除时请先核对并暂存预期删除，不要绕过检查。
- build 成功不等于 Worker runtime 正确；
- HTTP 200 不等于 Cache、PPR、prefetch 或 revalidation 正确；
- Wrangler dry-run 不等于已部署；
- Preview 可访问不等于当前 SHA 已部署；
- R2 binding 和 artifact 正确不等于真实写入成功；
- Airtable canary 不证明 Resend 投递和 owner 收件；
- 本地 `origin/main` guard 可被 `--no-verify` 绕过，不能替代 GitHub branch protection。

首次在新 worktree 使用本地 hook 时运行 `pnpm hooks:install`。不要提交 `.git/hooks` 生成文件或机器绝对路径。
